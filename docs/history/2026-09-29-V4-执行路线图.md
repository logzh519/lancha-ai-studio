# TikTok 电商视频生产系统 V4 — 执行路线图

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. 本文件是阶段级路线图：每个任务给出文件、接口与验收标准，不含逐步代码；子代理按 TDD 自行展开步骤（先写失败测试 → 运行确认失败 → 最小实现 → 运行通过 → 提交）。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `backend/docs/架构设计-V4.0.0.md`（下称「设计文档」）实现单管线视频生产系统：一个任务 = 一个 ASIN = 一条视频，从建单信息补全跑到 TikTok 文案，发布由管线外的发布模块完成；单机部署。

**Architecture:** PostgreSQL 同时作为唯一真相源与队列持久层；worker 进程内按通道（channel）批量领取节点，领取时一并抢占本通道的过期租约，租约 + fence 防双写，`external_call` 幂等账本防重复扣费；准入由数据库触发器 `pg_notify('admit')` 驱动，周期维护是 worker-main 进程内的定时协程；不设任何独立后台进程。Tool 只封装业务能力，不碰编排状态。

**Tech Stack:** Python 3.14、SQLAlchemy 2.1（新增 AsyncEngine，驱动 psycopg 3 异步）、psycopg 3（`LISTEN` 用原生 `AsyncConnection`）、Alembic、PostgreSQL 17（docker compose）、asyncio、FastAPI + gunicorn/uvicorn（阶段 3 引入）、Playwright 异步 API（阶段 5 引入）、prometheus_client（阶段 8 引入）、pytest + pytest-asyncio。

## Global Constraints

- 代码根目录 `backend/`，包前缀 `src.`，测试在 `backend/tests/`，从 `backend/` 目录运行 `pytest`。
- 时间字段一律 `BIGINT` Unix **秒**，应用层统一经 `src.common.clock.now()` 获取（测试可冻结）；SQL 函数 `now_ts()` 返回同一单位（`extract(epoch FROM now())::bigint`）。设计文档中的 `lease_ttl`、退避、`interval_sec`、`submit_lease_sec` 均为秒。
- 数据库访问：调度、worker、API 走新增的 `AsyncEngine`；现有同步 `get_session()` 保留给 Alembic、脚本与测试夹具，不删除、不改签名。
- DDL 以设计文档第 6 章为准，逐字复制列名、类型、约束与索引名；`node` 不分区（D21）。**不建** `maintenance_job`、`job_slot`、`node_subjob`，也没有 `quality_gate` 列。
- 所有 node 状态推进必须是条件更新 `WHERE status = :frm`（D9）；所有终态写回与心跳续期必须校验 fence（D7、D31）。
- 幂等键 = `sha256(f"{task_id}|{node_key}|{version}|{attempt}|{digest(input_snapshot)}")[:64]`，`retry_count` / `recover_count` 不参与（D8）。
- Tool 内禁止同步阻塞调用（`requests`、`time.sleep`、Playwright 同步 API）；现有同步的 `ObjectStorage` 由 `StorageService` 用 `asyncio.to_thread` 包装后注入。
- 审核：`review.mode` 只有 `"off"` 与 `required`，YAML 中写 `"off"`，解析器同时兼容布尔 `false`；**不做**自动质检、抽检采样、审核 SLA。
- 输入表达式只支持设计文档 7.4 的子集，不支持函数、运算、`[*]`（D19）。
- 不引入 Redis（D23）；不实现第 18 章子作业（M6 不在范围）。
- 部署为单机：API、worker-main、worker-browser、PostgreSQL 各一个进程（组），由进程守护自动重启（16.1）；`three_view`、`seedance` 通道与发布模块只在 worker-main 中承载。
- 前端（审核台、发布台）不在本路线图范围（仓库目前只有 `backend/`），本路线图只交付其所需的后端 API。
- 每个任务结束提交一次 git commit，提交信息用中文，`feat:` / `test:` / `chore:` 前缀。

### Task 1.4：节点创建、就绪推进与失败传播

**Files:**
- Create: `backend/src/scheduler/__init__.py`、`backend/src/scheduler/advance.py`
- Test: `backend/tests/scheduler/test_advance.py`

**Interfaces（Produces）：**
- `async create_task_nodes(s: AsyncSession, task: Task, pipeline: PipelineDef) -> None`
  - 创建全部节点，`version=1`；根节点 `ready`，其余 `pending`。
  - 冗余写入 `batch_id`、`created_by`、`channel`、`tool`、`max_retries`、`priority`。

- `async advance_task(s, task_id) -> None`
  - 锁 task；
  - 依赖满足的 `pending` 节点推进为 `ready` 或 `skipped`；
  - `blocked` 且上游已全部完成的节点置回 `pending`；

- `async refresh_task_progress(s, task_id) -> None`
  - 刷新 `task.progress`，并按 8.6 规则设置任务状态：全部 `completed`/`skipped` → `completed`；任一 `failed` → `failed`；存在 `awaiting_review` → `awaiting_review`；否则 `running`。

**验收：**
- 模拟 N3/N4 并行：N4 可独立完成；N3 失败后仅 N5 起下游 `blocked`；
- 对 `running` 节点调用 `advance_task` 不改变其状态（D9 回归用例）；
- 节点进入 `awaiting_review` 后任务为 `awaiting_review`；
- 全部完成时任务 `completed`。

### Task 1.5：批量领取、过期租约抢占、心跳与 fence

**Files:**
- Create: `backend/src/scheduler/claim.py`、`backend/src/scheduler/lease.py`
- Test: `backend/tests/scheduler/test_claim.py`、`backend/tests/scheduler/test_lease.py`

**Interfaces（Produces）：**
- `ClaimedNode`：节点行 + `fence: int` + `lease_until: int` + `recovered: bool`。
- `async claim_batch(channel: str, take: int, per_owner_take: int, worker_id: str) -> list[ClaimedNode]`，按顺序：
  1. 本通道每 15 秒至多一次，按 8.5 的 SQL 抢占过期租约：所属任务 `cancelled` 的节点置 `cancelled` 并删租约；其余覆盖为自己的租约与新 fence，`recover_count + 1`，`attempt` 不变，节点保持 `running`。
  2. 剩余名额逐字执行 8.4 的 LATERAL SQL，同事务发放租约并置 `running`。
- `lease_ttl_s(timeout_s: int) -> int`，等于 `min(timeout × 1.5, 3600)`。
- `async renew_lease(node: ClaimedNode, worker_id: str, on_lost: Callable[[], None]) -> None`：心跳协程。
  - 每 `lease_ttl / 3` 执行带 fence 条件的续期。
  - 影响 0 行时记 `node_lease_lost` 并调用 `on_lost`；数据库异常只重试，不取消。
- `async release_lease(s, node_id, worker_id, fence) -> None`。
- `async fenced_update(s, node_id, worker_id, fence, values: dict) -> bool`：8.5 的 `EXISTS` 校验写法。返回 `False` 时调用方丢弃结果，并记 `node_write_fenced`。

**验收：**
- 暂停批次、暂停任务、`next_run_at` 未到的节点不被领取；
- 两个运营各 50 条 ready 时，单次领取交替取数；
- 过期租约被抢占后 `recover_count + 1`、`attempt` 不变、fence 递增；所属任务已取消的节点被置为 `cancelled`；
- 旧 fence 的续期影响 0 行并触发 `on_lost`，旧 fence 写回返回 `False`；
- 并发两个协程领取同一通道，无重复节点。

  2. 首次执行写 `input_snapshot`，同一 version 只写一次；
  3. `asyncio.wait_for(tool.execute, timeout)`，被取消时不写回；
  4. 校验输出 schema；
  5. 调用 `on_success` 或 `on_failure`。
- `on_success`：本阶段只做 fence 写 `output`、置 `completed`、调用 `advance_task`；审核判定在阶段 4 插入。
- `on_failure`：
  - 按 8.8 伪代码处理，退避 `[30, 120, 600]` 秒；
  - 可重试时 `attempt + 1`、`retry_count + 1`，置 `ready` 并释放租约；
  - 否则置 `failed` 并 `propagate_failure`；
  - `tool.waits_external` 为真时，`wait_for` 超时按 `upstream_wait_timeout` 处理（`non_retryable`）。
- `RunnerContext(worker_id, registry, bucket, breaker, metrics)`。
- `async channel_loop(channel: str, ctx_factory, stop: asyncio.Event) -> None`：
  - 槽位填充式领取：`free = max_concurrent - len(inflight)`，`take = min(free, bucket.available())`，半开时 `take = 1`；
  - 不做内存预取；
  - 空闲时经 `LISTEN` 唤醒或按 `poll_interval_ms` 睡眠；
  - 每轮调用 `reload_if_changed()` 热加载配置。
- `async drain(inflight, grace_s=60)`：优雅停机。超时仍未完成的节点删除租约、置回 `ready`，不计 `retry_count`。

**验收：**
- 可重试错误走退避，且 `attempt` 递增；
- `non_retryable` 直接 `failed`，下游 `blocked`；
- 心跳续期可观测；租约被抢占后本地执行被取消、不写回；
- 停机时未完成的节点回到 `ready`。

## 执行方式

- 按阶段顺序执行；阶段内按任务编号顺序派发子代理。每个任务完成后先做规格符合性审查，再做代码质量审查，通过后提交，再进入下一个任务。
- 每个阶段结束时运行该阶段的验收用例全集并向用户汇报，确认后再进入下一阶段。
- 遇到依赖待确认问题（Q 编号）的任务：先实现接口与假实现，真实对接留到问题确认后补一个实现类，不阻塞后续任务。
